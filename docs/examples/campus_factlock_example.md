# Campus FactLock Example

本示例基于 `tests/golden_corpus/08_campus_factlock` 的“校园智能体创意赛通知”，展示 V1.8-draft 如何处理通知、公告和海报中的字段级事实锁定。它只说明领域语义，不实现 FactLockV1、字段级 Revision 数据库、通知解析 Agent、真实 QA 或日历校验器。

## 1. 最终有效 FactLock 字段

| 字段 | 最终有效值 | EvidenceRef | 备注 |
|---|---|---|---|
| 报名截止 | 10月25日18:00 | P03, P05, P12 | 初版创建，更正确认不变 |
| 材料截止 | 11月10日22:00 | P08, P12 | 第二份补充新增 |
| 决赛日期 | 11月17日星期日 | P05, P12 | 第一份更正覆盖初版 |
| 报到时间 | 8:00至8:40 | P04, P06, P12 | 时间不变 |
| 报到地点 | 科创中心一楼大厅 | P06, P12 | 第一份更正覆盖初版 |
| 开幕时间 | 9:00 | P04, P06, P12 | 时间不变 |
| 开幕/主会场 | 科创中心二楼多功能厅 | P05, P12 | 第一份更正覆盖初版 |
| 展示开始 | 9:20 | P04, P06, P12 | 时间不变 |

## 2. 字段级 Revision 示例

| Revision 来源 | 字段动作 | 字段 |
|---|---|---|
| 初版通知 P01-P04 | created | 决赛日期=11月16日星期六、主会场=创新楼报告厅、报名截止=10月25日18:00、名额=30支队伍、报到地点=创新楼一楼大厅 |
| 第一份更正 P05-P06 | overridden | 决赛日期改为11月17日星期日；主会场改为科创中心二楼多功能厅；报到地点改为科创中心一楼大厅 |
| 第一份更正 P05-P06 | confirmed_unchanged | 报名截止仍为10月25日18:00；报到时间、开幕时间、展示时间不变 |
| 第二份补充 P07-P08 | overridden | 现场名额由30支队伍增加到36支队伍 |
| 第二份补充 P07-P08 | added | 材料截止=11月10日22:00；一页项目摘要和不超过三分钟演示视频 |
| 旧海报 P09 | stale | 11月16日、创新楼、30强现场赛 |

后续通知没有提到某字段时，不表示整份覆盖或清空旧字段。第二份补充通知只覆盖名额并新增材料要求，不覆盖第一份更正中的主会场和报到地点。

## 3. 旧海报 STALE 示例

```yaml
old_poster:
  evidence_ref: P09
  visible_text:
    - "11月16日"
    - "创新楼"
    - "30强现场赛"
  status: STALE
  stale_reason:
    - "日期被 P05 覆盖为 11月17日星期日"
    - "主会场被 P05 覆盖为 科创中心二楼多功能厅"
    - "现场名额被 P07 覆盖为 36支队伍"
  must_not_override_canonical: true
```

旧海报可以作为历史视觉资产或“过期信息”剧情素材，但不能作为最终通知字段来源。

## 4. 数字单位区分

| 原文数字 | 单位 | 可确认含义 | 不可改写为 |
|---|---|---|---|
| 30 | 支队伍 | 初版现场决赛名额 | 30名学生 |
| 36 | 支队伍 | 最终现场决赛名额 | 36名学生 |
| 2至4 | 名学生/队 | 每队人数范围 | 固定每队4人 |
| 3、6、9 | 支队伍 | 一二三等奖队伍数量 | 获奖学生人数 |
| 18 | 支队伍 | 奖项队伍总数的计算结果 | 前18名学生 |
| 3分钟 | 视频时长上限 | 演示视频不超过三分钟 | 材料提交时间 |

“最多36支队伍，每队2至4人”只能推出容量范围，不能推出固定参赛人数。

## 5. 周舟与周洲不可合并

| EntityMention | 推荐表达 | EvidenceRef |
|---|---|---|
| 周舟老师 | Character/Contact: 咨询联系人，电话 0551-6360-2186 | P03, P12 |
| 周洲副院长 | Character/Contact: 开幕致辞人 | P10, P12 |

P10 明确两人不是同一人。姓名读音接近、同在学院通知中出现，不能作为 EntityAlias 合并证据。

## 6. 报到地点与主会场不可混画

```yaml
check_in_panel:
  event: "报到"
  story_time: "11月17日 8:00-8:40"
  location: "科创中心一楼大厅"
  evidence_refs: [P06, P12]
  must_not_show:
    - "三楼报告厅"
    - "二楼多功能厅作为报到地点"

opening_panel:
  event: "开幕"
  story_time: "11月17日 9:00"
  location: "科创中心二楼多功能厅"
  evidence_refs: [P05, P12]
  must_not_show:
    - "创新楼报告厅"
    - "一楼大厅作为开幕主会场"
```

报到地点和开幕/主会场可同属科创中心，但楼层和功能不同，漫画不能混画成同一地点。

## 7. 日期/星期冲突 QA 示例

| Observed | Expected | QAIssue |
|---|---|---|
| 11月17日星期六 | 11月17日星期日 | text_accuracy hard_failure |
| 11月16日星期六 | 11月17日星期日 | stale_fact hard_failure |
| 11月17日但省略星期 | 11月17日星期日 | 取决于 PanelSpec，完整通知可 hard_failure，背景板可 completeness issue |

日期和星期是成对 FactLock 字段。若画面目标是正式通知或海报正文，通常要求 text_accuracy=1.00。

## 8. 省略办公电话的边界

| 场景目标 | 省略电话的判定 |
|---|---|
| 完整咨询信息通知页 | hard_failure 或 high severity，因为 P03 明确给出电话 |
| 报名信息摘要卡，PanelSpec 明确只展示邮箱 | completeness issue 或可接受省略 |
| 剧情背景板，电话不可读且未改写其他事实 | soft/medium issue，按信息完整度复检 |
| 把电话改成其他号码 | text_accuracy hard_failure |

是否硬失败取决于 PanelSpec 的展示目标和 FactLock 范围，不应机械地把所有省略都判为同一等级。
